# OlegWeb

Personal website and notebook. Plain Markdown files in, plain HTML out.
Only needs Python 3 (no packages to install).

## Daily use

```sh
./blog new "Title"     # new entry dated now, opens in your editor
./blog new             # asks for a title; empty = today's date as title
./blog edit            # open the newest entry
./blog serve           # live preview at http://localhost:8000 (reloads on save)
./blog list            # all entries, drafts marked
./blog build           # build the public site into docs/
./blog publish "msg"   # build + git commit + push
```

In VS Code: **Terminal → Run Task…** has the same commands (`Notebook: …`).
Snippets in `.md` files: `img`, `todo`, `math`.

## Where things live

| Folder / file     | What it is                                                       |
|-------------------|------------------------------------------------------------------|
| `posts/`          | Notebook entries, one file each: `YYYY-MM-DD-slug.md`             |
| `pages/`          | Fixed pages: `about`, `projects`, `resume`, `cv`, `home` (intro) |
| `files/`          | PDFs and images, served at `/files/...`                          |
| `site.json`       | Name, tagline, links, site URL, domain                           |
| `theme/`          | `layout.html` and `style.css` (colors and fonts are at the top)  |
| `engine/`         | The generator. You shouldn't need to touch it                    |
| `docs/`           | Generated public site (deploy this). Don't edit by hand          |
| `.preview/`       | Generated by `serve`, ignored by git                             |

## Entries

```markdown
---
title: "On eigenvalues"
date: 2026-10-25 21:40
tags: [math, ideas]
draft: false
math: true
---

Text in Markdown.
```

- `title` can be empty: the date is used instead.
- `draft: true` shows the entry in the preview but keeps it off the public site.
- `math: true` turns on KaTeX: `$x^2$` inline, `$$ ... $$` on its own lines for display math.
  Write `\$` for a literal dollar sign in those entries.
- `summary:` (optional) replaces the auto summary shown on the front page.
- `<!-- comments -->` are private notes and never reach the site.
- Several entries on the same day are fine; they sort by `date` time.

Markdown supported: headings, **bold**, *italic*, ~~strike~~, ==highlight==, `code`,
fenced code blocks, links, images, lists, `- [ ]` task lists, `>` quotes, tables, `---`.
An image with a title gets a caption and a strip of tape:
`![alt](/files/photo.jpg "Caption")`.

Keyboard on an entry page: ← older, → newer.

## Pages, resume and CV

Each file in `pages/` becomes `/<name>/` with a tab in the top nav.

```markdown
---
title: Resume
nav: 3            # tab order; `nav: false` = no tab
file: resume.pdf  # optional: files/resume.pdf gets a download button + inline viewer
---
```

A page with no text and no file is an **empty slot**: the preview shows a dashed box
saying what to fill in, and the public site leaves it out until it has content.
To add a new page, copy one of the files in `pages/` and rename it.

## Publishing

`docs/` is a complete static site that works from any host or subfolder.

- **GitHub Pages:** push the repo, then Settings → Pages → *Deploy from branch*, folder `/docs`.
- **Cloudflare Pages:** build command empty, output directory `docs`.

Set `"url"` in `site.json` (e.g. `"https://example.com"`) to get an RSS feed (`/feed.xml`)
and canonical links. Set `"domain"` to have a `CNAME` file written for GitHub Pages.
Links in `site.json` with an empty `url` are hidden.
